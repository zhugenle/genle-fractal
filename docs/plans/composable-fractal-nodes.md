# 可组合分形节点系统规划

日期：2026-10-14。状态：设计方案，尚未实现。首期导出范围已由用户确定：可编辑节点图 JSON＋本项目公式包。

## 1. 目标与现状

目标是让用户搭建新的形态计算逻辑，而不只是用节点卡片操作一个固定公式。完整系统应支持：添加多个公式实例、自由连接合法端口、拆解迭代算子、混合生成新分形、公开关键参数、保存为可复用公式，再在工作室中加载。

本次检查基于主工作区 `D:\CodeX\web_release\web_fractal`，分支 main。工作区已有大量架构迁移改动；本次仅增加规划文档，不覆盖已有改动，不读取或操作其他工作树，不发布。

实际接入的最新公式是 UBER BULB V3.0 与 SPIKED CUBE IFS V1.0。其他工作树中的公式不假定已经可用。未来公式按同一注册接口加入。

已核对 `docs/ARCHITECTURE.md`、`docs/CODEX-WORKFLOW.md`、相关 AGENTS、`src/contracts/FORMULA-V1.md`、`RENDERER-V1.md` 及两份公式核心。当前限制：

- `evaluateFormula(world)` 返回 vec2：世界距离估计与轨道数据；不是通用节点求值协议。
- UBER 使用 A–I；SPIKED CUBE 额外使用 SC0–SC2。多实例不能直接共享这些全局 uniform。
- 现有节点编辑器主要适配固定公式参数，尚无通用类型系统、图编译器或用户循环编译能力。
- 页面片段在同一 IIFE 内组合，仍有词法依赖；新引擎必须通过显式接口接入，不能随意重新排列片段。
- 工作室与旧节点页的画质编码、动画和材质 profile 不同，保持兼容是独立要求。

## 2. 两种混合，分别实现

| 层级 | 用户操作 | 实际数学行为 | 实现阶段 |
| --- | --- | --- | --- |
| 完整公式组合 | 多个公式、变换、并集/交集/差集、平滑连接 | 对多个距离场进行空间组合 | 首个可用版本 |
| 迭代内部组合 | 折叠、排序、幂变换、反馈、偏移、旋转、条件分支 | 改写每轮 z 的演化，形成新的混合迭代分形 | 第二个核心版本 |

两者都保留。首期完整公式节点作为复合节点，后续提供“展开为子图”，保持原版实现作为可核对的参考。拆解不能无损时标明差异，不能静默替换。

首期不提供任意代码节点、无限循环、跨帧状态反馈或 Octane OSL 导出。GLSL/OSL 后端另列阶段；导出公式包不等于完成跨软件渲染复现。

## 3. 端口和连接规则

图是有类型的计算程序。端口类型、单位与坐标空间共同决定是否能连接。

| 类型 | 用途 | 规则 |
| --- | --- | --- |
| Float / Int / Bool / Vec3 | 参数、常量与普通运算 | 显式标量广播；Int 不隐式变循环结构 |
| Angle | 旋转和相位 | 区分 degree/radian，跨单位使用转换节点 |
| Position | 世界或局部采样坐标 | 携带空间标签与距离尺度变换信息 |
| OrbitState | 迭代状态 | 只能在指定 Iterate 容器内连接 |
| Field | 可在位置上求值的距离场 | 是函数表达式，不是已经算好的一个 float |
| SurfaceSignal | 轨道/材质选择信号 | 带语义和归一化策略，不与距离混用 |

设计约束：

1. 普通图必须是 DAG；反馈只在 Iterate 的状态输入/提交接口中成立。
2. 每个输入至多一条线，输出可分叉；多路输入使用明确的合并节点。
3. 图有一个指定的 Formula Output；允许保留未接入输出的实验节点，但它们不参与编译。
4. 参数越界、必填端口缺失、单位不符、非法环、未知节点版本给出节点级错误。
5. 字段变换必须把新坐标传播到上游场的求值中；不能对一个已经求值的距离数字“旋转”。
6. 分支条件区分全局参数与逐采样条件，成本估算考虑后者的 GPU 分歧。

## 4. 首期节点库

### 4.1 基础与完整公式

常量、向量构造/拆分、参数输入、范围映射、角度转换、世界位置、公式输出；UBER BULB、SPIKED CUBE 两个独立复合节点。每个公式实例拥有独立参数和 uniform 命名空间。

场变换首期支持平移、旋转、正的均匀缩放；非均匀缩放随后加入并按最小奇异值校正距离下界。重复、扭曲、位移等非刚性变换必须提供边界和导数规则后接入。

场组合首期包括并集，以及带距离语义限制的交集/差集/平滑并集。现有分形输出是近似 DE，交集和差集所需的内部符号不默认可信：必须先验证具体公式的内部定义；不满足时禁用相应端口组合或作为明确的实验模式。精确 SDF 测试节点用于验证这些运算本身。

平滑并集属于隐式表面造型，不宣称输出仍是精确距离。线性插值两个 DE 也不命名为“迭代混合”。节点面板显示各自含义。

### 4.2 UBER BULB 拆解目标

| 算子 | 对应当前逻辑 | 需要保留的状态/语义 |
| --- | --- | --- |
| 坐标入口与 Julia 常量 | AbsoluteScale/XYZ、JuliaXYZ | 初始 z 与常量 c 的区别；当前轴顺序 |
| 柱坐标转换 | 两个 Cylindrical 开关 | 对 z 与 c 分别转换 |
| 球心径向重映射 | Radius、MinRad、MaxRad、nonconformal、中心 | 当前是 Radius/r 再 clamp，不误写为经典 r² 球反演 |
| Euler 旋转 | AngYZ/XZ/XY | 原顺序与符号 |
| 球坐标幂变换 | Power、LoopPI、LoopPI2、ZMultiplier | 角度单位、半径与逃逸检查位置 |
| 记忆反馈 | PrevVecMul、OldVecMul | oldz、prevz 的原始更新顺序 |
| 常量递推 | Implode、Explode | 每轮 c 的变化，不当作固定 Julia 常量 |
| 正弦轴变换/分式乘法 | BrotMOD/Freq、fractionary | 奇点处理及距离可靠性下降 |
| 轨道采样与 DE 输出 | ColorIterations、dr、r | 原版兼容模式与新安全策略分开 |

### 4.3 SPIKED CUBE 拆解目标

绝对值折叠 → 三轴排序 → 尖刺分段折叠 → y 轴脊线夹取 → z 轴折叠 → 缩放/偏移/常量注入 → 扭转/Euler 旋转 → 轨道采样 → 立方体距离输出。

保留 CubeSymmetry 在入口的作用、acc/dr 双尺度与 DistanceSafety 混合方式、ObjectYaw 的世界变换。其 Bailout 当前比较 dot(z,z)，与 UBER 的半径/幂半径检查不同，UI 和节点定义明确标为“平方半径阈值”，不共用同名参数后偷换含义。

### 4.4 混合迭代模式

先支持每轮按顺序执行多个算子、每 N 轮交替算子、按迭代索引分段切换。之后再支持两分支的状态加权混合；这需要同时传播导数/边界，不直接混合两个场距离。

复合公式不是自然可串联的 OrbitState 算子。UBER 与 Cube 的完整节点可空间组合，但“幂变换接折叠”需要先拆出共享状态协议。

## 5. 显式迭代容器

Iterate 包含 Init、Body、Commit、Stop、Finalize 五个部分。Body 是内部 DAG；跨轮状态只能通过注册的 State Read/Next State 接口流动。

状态至少包含 z、c、previous、older、radius、iteration、trap 与距离跟踪数据。各算子声明读写字段、坐标空间和距离传播能力。

每轮读取当前状态快照，按显式依赖求值，最后提交下一状态。UBER 的 prevz=oldz、oldz=zv 用两个 next 字段表达，避免更新顺序因连线布局改变。合法图不允许同一个状态字段出现多个未合并的写入。

Stop 节点声明检查阶段：变换前、变换后或 Commit 后。兼容 UBER 的 r 与 powr 两次 bailout、近零退出；兼容 Cube 的平方半径检查。不能把所有公式强行改成一个通用末尾 bailout。

循环次数有编译期上限与运行期 uniform。结构改变触发编译；在固定上限内调次数只更新参数。首批只支持单层迭代，嵌套循环不进入默认节点库。

## 6. 距离估计与渲染稳定性

这是系统的主要技术风险。可连接不代表可安全光线步进。Sphere tracing 的安全性依赖有效距离/导数界，而不只依赖最后的数值看起来像距离。[Hart 的原始研究说明](https://experts.illinois.edu/en/publications/sphere-tracing-a-geometric-method-for-the-antialiased-ray-tracing/)

为每个 Field 记录：distanceKind（exact / conservative / heuristic）、insideSign（defined / unverified）、空间单位、已知域、边界依据、适用参数范围、奇点标记。

- 刚体变换保留距离性质；均匀缩放正确换算世界单位。
- 折叠、缩放、幂映射逐项定义 Jacobian/Lipschitz 传播。复杂历史反馈可能需要增广状态，不能只乘一个 z 导数。
- UBER 当前 dr 没有完整覆盖所有反馈、径向重映射和实验算子，归为 heuristic 兼容实现，不宣称严格保守。
- Cube 的现有 Lipschitz 策略先保留并做边界验证；不能将经验通过当作对任意图的数学证明。
- 缺少可证明规则的图可在实验模式预览，使用更保守步长、最大步长限制、有限步数和局部细化；这些措施不能保证消除漏面。
- NaN/Infinity、奇点和超界返回诊断；不静默夹成“有表面”的零距离。保留最后正常渲染及错误提示。
- 法线、阴影、AO、反射必须使用同一编译场；不得主表面已更新、阴影还调用旧公式。

距离策略随公式包保存。可靠性不能由用户改标签提升；实验图加载到工作室时保留其限制说明。

## 7. 图编译与运行接口

流程：Graph JSON → schema 校验 → 类型/空间/单位检查 → 版本解析 → 标准化 IR → 循环与距离分析 → GLSL 生成 → 实际 GPU 编译/链接 → 原子替换 Program。

IR 独立于节点位置、HTML 与 GLSL 字符串。每个节点定义版本、端口、参数、距离规则、CPU 参考求值（适用时）、GLSL lowering。只注册受控节点实现，JSON 不携带执行 JavaScript。

关键机制：

- 为每个实例生成稳定的参数绑定与符号名；A–I/SC0–2 通过兼容 adapter 转为实例参数，不能共享全局值。
- 复合 kernel 首期可生成为独立函数并显式传入参数；公式 helper 去重，避免函数重名或错误合并不同常量实例。
- 纯公共子表达式可复用；同一场在不同位置的求值不能错误缓存为同一次结果。
- 仅结构/节点版本/编译常量进入 Program 缓存键；滑块值进入 uniform。布局移动不重编译。
- 编译过程有 revision 标识；较旧结果不能覆盖较新图。编译失败保持最后成功 Program，错误定位到节点和生成源码行。
- 新旧 Program、buffer、uniform binding、context loss 恢复有明确生命周期，重复编辑不泄漏。
- CPU 图分析和代码生成可移入 Worker；GPU 编译仍需要管理其浏览器上下文，不能假定 Worker 自动解决驱动阻塞。

新增可选 Graph Formula Runtime 接口，保留旧 FORMULA-V1：compileGraph、installCompiledFormula、updateGraphParameters、getDiagnostics、dispose。首期编译输出提供 evaluateFormula(world) 兼容包装；内部 richer FieldResult 不强迫旧公式修改。

消息桥新增版本化命令，而非改变现有 setParameters 的含义。保持同源与 iframe 来源校验；错误、编译状态和节点诊断通过明确事件返回。

材质来源与轨道值在合并节点中显式选择：并集取获胜分支，平滑混合记录权重；不同轨道定义先经映射再混合。几何图输出不自动携带灯光变化。

## 8. 节点图 JSON 与公式包

建议新格式分别标识 genle-fractal-graph / genle-fractal-formula，schemaVersion=1；实施时冻结正式 schema。现有 JSON 格式和存储键保持不变。

| 内容 | 节点图 JSON | 本项目公式包 |
| --- | --- | --- |
| 节点、稳定 ID、版本、连接、子图 | 完整保存 | 必须保存，可继续编辑 |
| 布局、注释、分组、折叠状态 | 保存 | 可选 editor 段 |
| 公开参数、范围、单位、默认值 | 保存 | 必须保存 |
| 当前参数值与时间驱动配置 | 保存 | 起始预设＋时间驱动；不依赖导出时钟 |
| 距离策略、依赖版本、归属许可 | 保存 | 必须保存 |
| 相机、灯光、材质、画质 | 可选预览状态 | 独立 previewPreset，不混入形态定义 |
| 自动生成 GLSL | 非必需 | 可作缓存，加载时校验/重编译图 |

公式包首期采用单个 JSON 文件，避免为了封装引入运行依赖。建议结构为 manifest、graph、parameters、defaultValues、distancePolicy、dependencies、previewPreset、editor。graph 是规范来源；缓存 shader 不是不可编辑的唯一源。

manifest 包含稳定 formulaId、名称、描述、schema/engine 兼容版本、内容指纹、作者与源公式署名。依赖锁定节点实现版本，不能自动升级后改变已导出形态。布局、当前播放时刻不进入形态指纹；节点结构和算法版本进入编译指纹，参数值另作预设指纹。

公开参数通过稳定 parameterId 绑定 nodeId＋字段，不通过节点显示名或数组下标。删节点时提示失效绑定；重命名节点不破坏预设。参数封装让使用者在工作室调整少数关键项，制作者仍可展开完整图。

导入先验证大小、节点数、类型、依赖、连接、公开参数和设备能力，再编译。未知节点保留原数据并显示占位错误，不执行，也不偷偷丢掉。缺失依赖、较新版本和不支持的 runtime profile 需要可读诊断。

工作室通过新增导入公式包入口注册会话内公式。首期不把导入包写进源码注册表，不默认永久安装；用户明确保存后进入新的、独立命名空间。撤销导入可恢复之前公式。

旧节点图和单公式预设继续原路径加载。可提供“复制为新图”迁移，原数据保留；历史图不被自动升级覆盖。

## 9. 编辑体验

沿用最新 index 的代码字体、黑白灰、可选主题色与 compact 控件。保留原工作室和旧节点页，新增实验入口建议 /composer，接入构建时确定最终路由。

布局：节点库＋图画布＋实时预览＋检查器。默认显示复合公式，高级用户再展开迭代容器。端口同时使用形状、文字和颜色识别；拖线时只高亮兼容输入，不能只靠颜色。

支持搜索添加、拖线改接、复制实例、框选、分组、框定全图、撤销重做、删除确认失效绑定。结构修改可短暂合并编译请求，参数拖动走 uniform 实时更新。手机先保证查看、选择节点和检查器调参可用；复杂布线以桌面为主，不承诺首期等效手势。

诊断呈现为“节点问题／编译中／成本／距离可靠性”。预览报错仍显示最后成功图，并明确标为旧结果，避免用户误认新连接已生效。

公开参数与“保存为公式”放在图级界面；不把节点布局、渲染画质和形态参数混在同一个面板。

## 10. 性能预算

保持当前 WebGL 底座，不以迁移 WebGPU 为首期前提。读取设备实际 uniform、精度等能力，估算图资源；WebGL 编译/链接和实现限制必须实际验证，不能按节点数量就推断所有设备可运行。[Khronos WebGL 1.0 规范](https://registry.khronos.org/webgl/specs/1.0.3/)

首期试验预算建议：输出可达节点不超过 64、昂贵复合公式叶节点先不超过 2、仅一层循环。它们是待性能测试调整的产品限制，不是硬件统一上限。迭代上限沿用具体算子的已知范围，不允许图整体随意变成无限成本。

两个完整场的组合可能使单次采样成本接近相加；法线、阴影与反射还会重复求值。使用采样成本、循环次数、分支、场叶节点数估算，而不是单纯数卡片。

目标参考已有约 30fps 动态预算，但复杂图不保证实时。性能策略降低光照采样/分辨率，不悄悄改变用户定义的数学迭代。低性能图提供静帧计算；导出锁定确定的公式参数、时间、渲染 profile 和输出尺寸。

建议新增 src/graph/（schema、类型、IR、编译、诊断、受控基础算子注册）；公式特有算子留在 src/formulas/<id>/nodes/，避免复制数学核心进 UI。

| 模块 | 变更职责 | 先决条件 |

| src/state/ | 图历史、公式包、兼容导入、公开参数和时间状态 | 新格式及迁移规则 |
| src/ui/nodes/ | 画布连线、检查器、诊断、composer 适配器 | 引擎与状态 API |

先接口和验证图，再引擎/renderer，再公式与状态，最后 UI 集成。若后续安排并行开发，每项任务使用独立工作树、codex/ 分支与独立端口；共享契约和构建配置仅由集成任务维护。当前不创建其他任务或发送消息。

| P2 迭代子图 | Cube 折叠子图、UBER 幂/反馈子图、显式 Iterate、距离分析 | 展开参考图复现原公式；混合顺序/交替产生不同稳定形态；非法反馈被阻止 |
| P3 产品完善 | 复合节点封装、时间驱动、参数映射、可靠性/成本诊断、编辑体验 | 撤销/复制/版本缺失/context loss 可恢复；旧预设回归通过 |
| P4 可选外部后端 | 独立 GLSL 包、限定子集 OSL 导出 | 每种算子有后端覆盖表；不支持部分明确报告，跨后端数值验证 |

阶段估时在 P0 小型原型测量后给出。P2 的距离规则是最大不确定项；先完成 Cube 的分段仿射折叠链，再做 UBER 的幂、历史反馈及实验分式。不得以完整 UI 完成来掩盖编译器尚未成立。

### 首个开发批次：P0＋P1 最小闭环

1. 冻结 graph/formula-package schema，做一个手写参考图。
2. 建立两种完整公式的独立实例绑定，单节点输出与原版一致。
3. 用精确球/盒 SDF 验证变换与 CSG，再接两种近似分形场的并集。
4. 完成独立旋转/缩放＋并集生成 GLSL，真实浏览器编译与预览。
5. 打通图 JSON、公式包导出/导入及工作室公开参数。
6. 最后加节点库、连线操作、检查器和错误定位。

首批不扩展材质编辑器、不统一旧画质策略、不改既有相位默认值，避免同时改变画面和形态使回归无法判断。

## 13. 验证样本与发布门槛

- 单 UBER、单 Cube：固定参数/相位/相机/profile，对照原公式距离采样与渲染；图展开前后一致性明确容差和浮点差异。
- 两个同种公式实例：改变实例 A 不影响 B，helper 与 uniform 不冲突。
- 平移/旋转/缩放：用具有解析距离的参考球/盒验证世界距离、法线与空间组合。
- 混合迭代：至少“折叠→幂”“幂→折叠”“奇偶轮交替”三图；验证循环状态和退出位置。
- 异常图：非法类型、未定义内部符号的差集、非容器环、过量循环、缺依赖、奇点；错误定位且最后成功图仍可恢复。
- 导出重载：同节点版本、参数、phase、profile 下数值和画面一致；布局变化不影响形态，重命名不破坏公开参数。
- 确定性：时间驱动保存起点/范围/周期/插值/闭合策略；重新载入不由当前墙钟随机决定形态。
- 性能：编译时长、程序替换次数、GPU 耗时、反复编辑资源释放，在代表性桌面与移动浏览器实测。
- 兼容：现有主页、旧节点页、存储键、旧 JSON、5/4 档画质映射、主/旧相位策略不变。

代码阶段运行 npm run check → npm run build → npm run check:dist，随后实际 GPU 编译、主页与节点预览及影响范围内桌面/手机检查。每一阶段通过后交付本地预览与可重载样本。发布单独接受用户指令；不推送 main 触发自动部署。

## 14. 已确定与待验证

已确定：首期节点 JSON＋本项目公式包；保留现有页面与格式；两级混合；显式 Iterate；受控编译；距离可靠性随图传播；模块分工先接口后调用方。

待 P0 验证：两公式的内部符号能否支撑 CSG、独立 kernel 参数化成本、参考图数值容差、各设备成本上限、导数传播可覆盖哪些 UBER 算子。未知能力不作为首期宣传承诺。

成功标准是“连线真正改变算法，保存后可继续编辑和复现”，不是节点卡片数量，也不是一次演示能出图。
